# AgroVision 2.2 — карточки товара из фотографий

Локальное приложение: FastAPI + CLIP + rembg + Canvas. Без платных API, без сборки frontend. Графика, подставки и фоны рисуются кодом. Интерфейс рассчитан на компьютеры.

## Изменения 2.2

- **Оформление:** слева стиль, визуальная галерея фонов, узор и палитры; справа большой закреплённый предпросмотр. Переключатель «Только фон» позволяет рассмотреть графику без товара. Превью обновляется сразу при выборе цвета, узора, шрифта или подставки.
- **Сведения и содержимое:** выбор 1–4 карточек перенесён на следующий этап. Каждый шаблон показывает настоящий мини-макет с загруженными фотографиями и текущими сведениями.
- **Новый генератор:** крупные заголовки, размещение по пропорциям изображения, контактная тень, размерные линии по фактическим границам размещённого фото, автоматические крупные планы и проверка контраста текста по поверхности под ним. При сложном фоне может появиться редактируемая подложка текста. Новые факты о товаре не добавляются.
- **Дополнительные изображения:** теперь используются во всех семействах шаблонов. «Автоматически» размещает вырезанные объекты как декор, непрозрачные фото — как окна с деталями. Можно явно выбрать декор, крупный план, комплектацию или исключить файл и указать свою подпись. Во избежание перегрузки обычная карточка добавляет до двух вспомогательных изображений; остальные распределяются по выбранным карточкам. «Комплектация» и крупные планы могут использовать до трёх окон. Если файлов много, проверьте выбранные макеты: не все пять обязательно окажутся на одной карточке.
- **Палитры:** вместо исключения всех светлых/тёмных пикселей используется альфа-маска либо удаление похожего фона, связанного с краями. Основные оттенки группируются в Lab и взвешиваются по площади, а не по яркости этикетки. Белый и чёрный считаются полноценными цветами. Палитры показывают товар на выбранном фоне, а опорный оттенок можно уточнить вручную. На сложных непрозрачных фотографиях это всё ещё эвристика; точнее работают изображения с удалённым фоном.
- **Редактор:** восемь точек на рамке меняют размер, ↻ над рамкой поворачивает объект. Фото по умолчанию сохраняют пропорции; Shift разрешает свободное изменение рамки. При повороте Shift задаёт шаг 15°. Углы текста масштабируют шрифт; боковые точки меняют ширину/перенос. Ручки учитывают уже заданный поворот и размер окна браузера, не попадают в PNG. Одно перетаскивание — один шаг отмены.

Сохранённые сцены остаются прежними. Чтобы увидеть новую компоновку, выберите оформление и соберите карточки повторно. Новые параметры сохраняются в том же формате проекта 2.

## Обновление и запуск

Рекомендуется Python 3.11 или 3.12. Откройте папку проекта в PyCharm, выберите своё виртуальное окружение. После обновления файлов **обновите зависимости**:

```bash
python -m pip install -r requirements-full.txt
python -m uvicorn backend_main:app --reload
```

Откройте `http://127.0.0.1:8000` в браузере. Запускайте команду из папки с `backend_main.py`. После обновления frontend обновите страницу через Ctrl+F5.

Если начинаете с нуля:

```bash
python -m venv .venv
```

Активация в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Активация в macOS/Linux:

```bash
source .venv/bin/activate
```

Для CPU на Windows/Linux перед полной установкой можно поставить CPU-версии PyTorch:

```bash
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements-full.txt
```

Для интерфейса без моделей достаточно `python -m pip install -r requirements.txt`: отключите удаление фона и предложение категории на первом шаге. Характеристики можно ввести вручную.

## Что изменено по визуальным примерам

Три направления оформления:

- **Уютный** — тёплый градиент света, поверхность под товаром, мягкие молочные ячейки, крупный заголовок.
- **Геометрия** — крупные диагональные или скруглённые цветовые плоскости, читаемые ячейки характеристик.
- **Минимализм** — свободное пространство, простые линии, спокойные оттенки и крупные фрагменты товара.

На карточку попадают максимум 1–3 подтверждённых свойства. Пустые ячейки и надписи «Укажите…» больше не рисуются. Если для размерных линий нет данных, приложение сообщает об этом под холстом. Размеры не угадываются по изображению.

Семь шаблонов содержимого: главная, характеристики, габариты, крупные планы, выноски, комплектация, акцент на детали. Выбор 1–4 шаблонов создаёт отдельные карточки. Добавлен вертикальный формат **3:4**, сохранены 1:1, 16:9 и 9:16.

Крупные планы и акцентная карточка сами приближают и кадрируют товар. Для двух деталей выбираются разные области по расположению непрозрачных пикселей. Это геометрическая эвристика, а не распознавание назначения детали. Дополнительные фото имеют приоритет. В редакторе можно изменить приближение и смещение внутри рамки. Прозрачные поля исходного PNG обрезаются автоматически, оригинал сохраняется.

### Фоны

Варианты: однотонный, градиент, арка, диагональ, геометрические ячейки, тёплый интерьер, световое пятно. Крупные формы намеренно ограничены по количеству.

На этапе оформления есть живой предпросмотр, цвета основного фона/второго оттенка/акцента, выразительность и направление градиента. Можно загрузить собственный интерьер или фон.

В редакторе справа вкладка **«Фон»**: изменение рисунка и цветов без пересборки товара и текстов; для фотографии — масштаб, смещение и тонировка. Изменяется текущая карточка. Сгенерированные фоновые слои заблокированы от случайного перетаскивания, их можно разблокировать в списке слоёв. Повторная настройка рисунка пересоздаёт только фоновые слои.

### Цвета и гармонизация

Палитры вычисляются по пикселям товара: прозрачные области и похожий на углы однородный фон исключаются по простой эвристике. Предлагаются «Тон в тон», «Мягкий контраст», «Тёплый нейтральный» и «Глубокий». Это подсказки для дизайна, не точная колориметрия или гарантия отделения объекта от сложного фона.

В редакторе **«Подобрать коррекцию»** измеряет яркость, разброс яркости и насыщенность товара и дополнительных фото. Предлагается мягкая коррекция, с учётом основного фото и цвета фона. Можно сравнить «до/после», применить ко всем карточкам или отменить предпросмотр. Фотография фона в такую коррекцию не включается. Изменения обратимы через «Отмена».

Коррекция не должна подменять настоящий цвет товара: значения ограничены. Яркость, контраст, насыщенность, поворот, прозрачность, масштаб и смещения представлены **ползунками** с текущими значениями. Геометрические координаты и размеры остаются точными числовыми полями.

### Подставки и редактор

Цилиндр рисуется как объёмная фигура с верхней эллиптической поверхностью, градиентной боковиной и тенью. Прямоугольная подставка — изометрическая платформа с верхом и двумя гранями. Цвет, размер и толщина меняются в свойствах.

Шрифты Manrope, Cormorant Garamond и DejaVu хранятся локально, поддерживают кириллицу; лицензии включены. Внешний CDN не нужен.

Кнопки и подписи увеличены, боковые панели имеют собственную прокрутку. На небольших экранах компьютера панели переходят под холст. Проверялись ширины 1024–2560 px; основное рабочее окно рекомендуется от 1280 px. Мобильный сценарий отдельно не оптимизировался.

Остались: порядок слоёв, скрытие, блокировка, удаление, дублирование, перемещение мышью, точные размеры, поворот, редактирование каждого текста, отмена/повтор, PNG и ZIP. Плашка и текст внутри неё — отдельные слои, группировка пока не реализована.

- Двойной щелчок по тексту — переход к текстовому полю.
- Стрелки — сдвиг на 1 px, Shift + стрелки — на 10 px.
- Delete / Backspace — удалить выбранный разблокированный элемент.
- Ctrl/Cmd + Z — отмена; Ctrl/Cmd + Shift + Z — повтор.
- «Вписать текст в блок» уменьшает шрифт при переполнении.

## Удаление фона: скорость и качество

По умолчанию используется **быстрый режим U²-Net mini (`u2netp`)** вместо тяжёлого BiRefNet. Есть выбор:

| Режим | Модель | Входной предел | Назначение |
|---|---|---|---|
| Быстро | `u2netp` | 1024 px по длинной стороне | Быстрый черновик на CPU, простые контуры |
| Сбалансированно | `u2net` | 1600 px | Альтернатива для общего выделения |
| Сложные контуры | `birefnet-general` | 2400 px | Детализация; существенно тяжелее |

Ограничение размера сокращает подготовку и постобработку; основное ускорение даёт замена модели. Маска возвращается к исходному размеру; исходные RGB-пиксели сохраняются. Быстрая маска может терять тонкие детали. Для шерсти и сложных границ попробуйте режим «Сложные контуры».

Дополнительно:

- PNG с прозрачным фоном не вызывает модель.
- Сессия каждой модели переиспользуется между фотографиями.
- ONNX Runtime ограничен четырьмя вычислительными потоками и одним межоперационным потоком, чтобы избежать избыточной конкуренции на CPU.
- Кэш результата зависит от содержимого исходного файла и модели; расположен в `results/cutout-cache/`. Повторный запрос того же фото не выполняет инференс.
- В интерфейсе видно реальное суммарное время обработки; для фото API сохраняет метод и время удаления фона. Это не таймер одной только нейросети.
- На этапе оформления можно выбрать другое качество для повторной обработки без новой загрузки фотографий.

**Первый запуск отличается от прогретого:** установка/импорт библиотек, загрузка весов и инициализация могут занимать заметное время. В этой Linux-среде реальная U²-Net mini проверена на синтетическом изображении 900×1100: первый запуск с первоначальным импортом/загрузкой занял около 64 с; после подготовки библиотек новый процесс с ограничением потоков обработал новый вариант за 2,17 с, следующую новую картинку в той же сессии — за 0,52 с. Чтение ранее готового результата из кэша — около 0,04 с. Это иллюстрация различия холодного запуска, инференса и кэша, **не сравнение скорости с BiRefNet** и не гарантия для вашего компьютера или фотографий.

Веса скачиваются из официальных источников, проверка TLS и контрольных сумм не отключается. При первом запуске нужен Интернет. При ошибке загрузки приложение покажет предупреждение и сохранит оригинал; после исправления можно повторить обработку.

## Распознавание

**Распознавание текста удалено** из обработки, интерфейса и зависимостей. EasyOCR больше не устанавливается и не запускается. Категорию предлагает локальная CLIP по изображению; это относительное сходство среди вариантов, не калиброванная вероятность.

Характеристики и описание вводятся пользователем. Источник новых фактов — `user`, каждому свойству нужно подтверждение. В автоматическую композицию попадают только подтверждённые свойства. Оценка готовности проверяет заполненность, необходимые поля демонстрационного профиля и ручное подтверждение, а не истинность всех заявлений.

## Проекты и данные

- `uploads/<uuid>/` — исходные фото, вырезанные изображения, фоны.
- `results/<uuid>.json` — сведения, оформление и сцены.
- `results/cutout-cache/` — вычисленные маски/изображения; можно удалить для очистки кэша.

При обновлении не удаляйте `uploads` и `results`. Уже сохранённые сцены автоматически не переделываются под новый стиль. Чтобы получить новую композицию, выберите оформление и снова нажмите «Собрать карточки»; замена ручных изменений требует подтверждения. «Сохранить сведения, оставить композиции» обновляет данные без пересборки текста на холсте.

«Сохранить» записывает все карточки на сервер. Последний UUID хранится в localStorage браузера. Автосохранения каждого движения нет.

Экспорт JSON содержит ссылки на локальные изображения, **фото в него не встроены**. Для открытия JSON нужно сохранить соответствующие `results` и `uploads`; при переносе на другой компьютер переносите обе папки. PNG и ZIP создаются в браузере одним и тем же рендерером, что и предпросмотр, без рамки выделения.

Обработка однопоточная, очередь в памяти процесса Uvicorn: используйте один worker. `--reload` или перезапуск прерывает текущую задачу, она будет отмечена как прерванная. Сохранённые фото и проекты остаются на диске.

Это конкурсная версия для локального использования без авторизации и разграничения доступа. Для публичного многопользовательского сервиса нужны изоляция проектов и внешняя очередь задач.

## API / интеграция

OpenAPI: `/docs`, JSON-контракт: `/openapi.json`.

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/health` | Готовность HTTP-сервера, не наличие всех моделей |
| POST | `/api/projects` | Multipart: `product_image`, повторяемое `details`, `remove_product_background`, `remove_details_background`, `background_quality` (`fast/balanced/detail`), `use_vision`; возвращает 202 |
| GET | `/api/projects/{id}` | Проект, состояние задачи, категория, оценка готовности |
| POST | `/api/projects/{id}/retry` | Повтор обработки; необязательный Form `background_quality`; 409 при уже работающей задаче |
| PUT | `/api/projects/{id}` | `{product, settings, scenes}`; сохранение недоступно во время обработки |
| POST | `/api/projects/{id}/background` | Form `image`, возвращает локальный URL |

`product.facts`: `{label, value, source: "user", confirmed}`. `product.confirmed` — ручная проверка всего набора сведений.

`job.status`: `queued`, `running`, `done`, `failed`, `interrupted`. `done` может сопровождаться предупреждениями о недоступной модели. `completed/total` считает завершённые попытки этапов, а не успешность каждого распознавания.

`scenes[]`: `{id, template, title, width, height, background, backgroundSettings, notes, nodes}`. Массив `nodes` — от заднего плана к переднему. Типы: `text`, `image`, `shape`, `line`, `pedestal`. Координаты в пикселях сцены. `backgroundRole` отделяет фоновые объекты при редактировании фона. Новая версия совместима с проектами формата 2; удалённые текстовые результаты старой версии не используются.

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m playwright install chromium
# Следующие команды — при запущенном сервере:
python tests/browser_smoke.py

```

Браузер можно указать через `CHROMIUM_PATH`, адрес сервера — через `APP_URL`. Для Windows/Linux/macOS тесты используют системную временную папку. Для тестового изображения в `browser_design.py` используется включённый DejaVu-шрифт.

Проверки покрывают сохранение/открытие, PNG/ZIP/JSON, редактирование, прозрачные фото, кэш и режимы удаления фона, отсутствие текстового распознавания, сохранение CLIP-контракта, 84 сочетания стиля/формата/шаблона, персональные палитры, ползунки, фон, гармонизацию и размеры окна компьютера. Модельные вызовы в API-тестах заменены адаптерами; отдельно выполнен реальный прогон U²-Net mini, описанный выше. Качество масок на ваших фото, CLIP и BiRefNet в этой среде не оценивались.

Новый `browser_composition.py` дополнительно проверяет видимость двух загруженных деталей по пикселям экспортного рендера, масштабирование и поворот настоящими мышиными жестами (включая повёрнутую рамку), одну отмену на жест, перенос выбора содержимого, расположение предпросмотра и отделение белых/чёрных/цветных товаров от фона в предложенных палитрах. Матрица из 84 вариантов теперь также включает загруженный прозрачный декор и непрозрачное фото детали.

Лицензии локальных шрифтов находятся в `frontend/fonts/`.

### Ракурсы и редактирование (2.3)

В основной загрузке можно выбрать сразу до восьми фото товара. Они займут отдельные слоты. Откройте меню под миниатюрой, чтобы указать ракурс, выбрать основное фото или удалить снимок. Фото деталей загружаются отдельно. Разные карточки используют разные ракурсы; в редакторе выбранный снимок заменяется нажатием на миниатюру.

Для настройки фрагмента дважды нажмите на фото или выберите «Изменить фрагмент на холсте»: перетаскивание двигает изображение внутри рамки, колесо меняет масштаб, Escape завершает кадрирование. Цвета изменяются сразу при движении в палитре. Обводка фото повторяет его прозрачный контур (для исходного непрозрачного снимка сначала удалите фон); её толщина и цвет находятся в свойствах. Эффект сохраняется в PNG и проекте.

Минимализм использует однотонный фон и характеристики без декоративных ячеек; уютный стиль сохраняет мягкие панели и тёплый свет. Новое оформление применяется при пересборке карточек.

Проверка новых действий: `APP_URL=http://127.0.0.1:8000 CHROMIUM_PATH=/usr/bin/chromium python tests/browser_angles.py`.
